### Duplicated across backends (for a follow-up issue, not fixed here)
1. Limine boot-memory segmentation — `usable_region_segments` +
   `subtract_reserved_range` (+ aarch64's `split_segment`) is the same
   algorithm in x86/src/lib.rs:626-676 and aarch64/src/lib.rs:2025-2066,
   differing only in panic text and in whether the split is factored out.
   x86 carries the unit test; aarch64 has none.
2. `align_up_usize` is byte-identical in x86/src/lib.rs:678 and
   aarch64/src/lib.rs:2068, while `helios_hal::align_up` already exists;
   `align_down` is separately redefined in x86/src/smp.rs:1385 and
   hosted/src/vmm.rs:406.
3. `read_debug_serial` / `write_debug_serial_bytes` — the same
   `helios_kernel::try_read_serial` + `ByteSerial::write_bytes` pair in
   x86, aarch64, riscv and (renamed) hosted; only the `ByteSerial` impl
   is backend-specific.
4. The panic console — `PanicSerialWriter` + `emit_console_line` in
   x86/src/lib.rs:1178 and aarch64/src/lib.rs:2079, and the same shape as
   riscv's `PanicConsole` inside `fatal_panic`.
Intra-crate (not §1, noted anyway): `read_be_u32` in both riscv/src/pci.rs
and riscv/src/net/mod.rs; the six-line virtio MMIO bring-up repeated across
aarch64's host_fs/net/entropy/block/vsock/balloon.
